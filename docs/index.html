系统架构与数据流

自上而下：数据源 → 采集编排 → 数据访问 → 统一存储 → 计算/应用 → 工具出口。虚线表示事件、派生或无强耦合的读取。

为什么是 FinBridge

不是又一个数据管道：把「研究结论可复现」写进模块边界、因子资产与报告口径。

WHY FINBRIDGE
01 / PIPELINE

一条链路，四层边界

采集、数据访问、因子计算与应用分层；单向依赖让每层可以独立替换与测试。

02 / FACTOR

因子是资产，不是脚本

声明式 FactorDef → registry → 长表 / latest；方向、单位、版本与依赖全部可追溯。

03 / RESEARCH

报告经得起复核

IC / NW-t、分层、衰减、成本、断言与失效归因；HTML 报告与评分卡同源。

04 / BACKTEST

A 股规则内置

T+1、整手、涨跌停、停牌、佣金与印花税；单标的与横截面共用一套账本。

05 / MCP

MCP 原生

行情、财务、因子、选股、持仓与同步统一暴露为工具，AI Agent 可直接调用。

06 / REPRODUCIBLE

可复现的运行

run_id 固化策略、参数、数据快照与执行规则；同输入可重跑，结论可对照。
